# Сайт рок-группы — регистрация, вход и профиль

ДЗ8 по веб-технологиям: React + TypeScript + Vite, деплой на GitHub Pages
через GitHub Actions. Бэкенд готовый, преподавательский.

Что умеет:

- регистрация нового музыканта;
- вход и выход;
- просмотр своего профиля;
- редактирование профиля (имя, специализация, «о себе», ставка за концерт).

## Запуск

```
npm install
npm run dev
```

## Бэкенд

`https://inai-col2.fishrungames.com` (Swagger: `/api/docs/`)

| Адрес | Что делает |
|---|---|
| `POST /api/register/` | регистрация, `{username, password}`, пароль от 6 символов |
| `POST /api/login/` | вход |
| `POST /api/logout/` | выход |
| `GET /api/profile/` | свой профиль |
| `PATCH /api/profile/` | правка профиля |
| `GET /api/specializations/` | справочник инструментов, работает без входа |

### Три вещи, на которых тут проще всего споткнуться

**1. `credentials: "include"` в КАЖДОМ запросе.** Сервер узнаёт нас по cookie
`sessionid`, а она приходит с `SameSite=None; Secure; HttpOnly`. Браузер
отправляет такую cookie на чужой домен только с этой настройкой fetch. Без неё
любой запрос к профилю вернёт `403 Учетные данные не были предоставлены`.
Вся настройка стоит один раз в `src/api.ts`.

**2. Заголовок `Session-Id` из Swagger в браузере НЕ работает.** Сервер
разрешает только заголовки `Authorization, Content-Type, X-Requested-With`,
`Session-Id` среди них нет — браузер заблокирует запрос ещё на префлайте.
В Swagger и в curl он проходит, в браузере нет. Поэтому только cookie.

**3. Ставка (`fee`) ломается на запятой.** Сервер принимает `2500` и
`"2500.50"`, но на `"2500,50"` отвечает `400 Требуется численное значение`.
На русской раскладке запятую ставят не задумываясь, поэтому в `ProfileForm.tsx`
она заменяется на точку перед отправкой. Обратно `fee` приходит строкой
вида `"2500.00"` — поэтому в типе это `string`, а не `number`.

Ошибки сервер шлёт в двух разных видах: `{"detail": "..."}` (401, 403) и
`{"поле": ["..."]}` (400). Разбирает их одна функция `errorText` в `api.ts` —
если разбирать только первый вид, на экране появится `undefined`.

## ❗ Что сделать перед деплоем

**1. Имя репозитория.** В `vite.config.ts` стоит `base: '/rok-gruppa/'`.
Это имя папки на GitHub Pages. Назовёшь репозиторий иначе — поменяй и эту
строку, иначе сайт откроется белым: стили и скрипты будут искаться не там.

**2. Включить Pages правильно.** Settings → Pages → Source выбрать
**GitHub Actions**, НЕ «Deploy from a branch».

**3. Положить проект в КОРЕНЬ репозитория.** `package.json` должен лежать
рядом с `.github`, а не внутри ещё одной папки — иначе Actions не найдёт его
и сборка упадёт на первом шаге.

После `git push` в `main` деплой запускается сам. Вкладка Actions покажет ход,
адрес сайта появится там же и в Settings → Pages.

## Что где лежит

## Разбор: что отвечать, если спросят

**Как сайт понимает, что пользователь уже вошёл?**
При открытии страницы `App.tsx` в `useEffect` запрашивает `GET /api/profile/`.
Ответ 200 — значит cookie жива, показываем кабинет. Ответ 403 — значит не
вошли, показываем формы. Поэтому 403 здесь не считается ошибкой и не
выводится красной плашкой.

**Где хранится то, что пользователь вошёл?**
Не в localStorage и не в коде. Хранит сервер — он выдаёт cookie `sessionid`
с пометкой `HttpOnly`, то есть JavaScript её прочитать не может, и украсть
через чужой скрипт тоже. Браузер сам прикладывает её к каждому запросу,
от нас нужна только строка `credentials: "include"`.

**Почему после регистрации не нужно отдельно входить?**
`POST /api/register/` возвращает 201 и сразу ставит cookie `sessionid`.
Поэтому в `AuthPanel.tsx` и вход, и регистрация просто передают наверх
полученного пользователя — дальше код одинаковый.

**Зачем `PATCH`, а не `PUT`?**
`PATCH` меняет только присланные поля. `PUT` заменил бы объект целиком, и всё,
что не отправили, затёрлось бы пустыми значениями.

**Почему в select варианты не вписаны руками?**
Список берётся с `GET /api/specializations/` и приходит парами
`{value, label}`: `value` (`guitar`) уходит на сервер, `label` (`Гитара`)
видит человек. Если преподаватель добавит на бэкенде новый инструмент,
список обновится сам, без правки кода.

**Что такое `specialization_display`?**
Русская подпись, которую сервер считает сам по коду специализации. Поле
только для чтения: отправлять его назад бессмысленно, поэтому в типе
`ProfileChanges` его нет.

**Зачем нужен `useState` для каждого поля формы?**
Это «управляемые поля»: значение берётся из состояния React, а `onChange`
кладёт в состояние новое. Так React всегда знает, что сейчас в форме, и
может подставить в неё данные, пришедшие с сервера.
